# 图像金字塔 · 多分辨率渲染 Demo

基于 **Canvas + Web Worker + TypedArray + IndexedDB + PerformanceObserver** 的
高斯/拉普拉斯图像金字塔构建与多分辨率瓦片渲染。

## 运行

```bash
python3 -m http.server 8000
# 打开 http://localhost:8000 （推荐 Chrome，可显示 JS 堆内存）
```

1. 选择尺寸（2048/4096/8192）点击「生成测试图并构建金字塔」，或「打开图片」加载本地大图。
2. 滚轮缩放、拖拽平移、双击复位；勾选「显示瓦片边界」验证瓦片对齐。
3. 点击「分层渲染基准」对比各分辨率层的渲染帧耗时与内存占用。

## 架构

| 模块 | 职责 |
| --- | --- |
| `js/pyramid-core.js` | 纯算法（UMD）：5x5 高斯核 REDUCE/EXPAND（可分离、镜像边界）、分条带上采样、拉普拉斯残差、瓦片切分 |
| `js/pyramid-worker.js` | Worker：合成测试图、逐层构建金字塔、流式写 IndexedDB，峰值内存 ≈ 2 层 + 1 个条带 |
| `js/idb.js` | IndexedDB 封装（tiles/meta 两个 store，window/worker 通用） |
| `js/tile-cache.js` | LRU 瓦片缓存，字节预算控制，超预算逐出并 `close()` 释放 |
| `js/renderer.js` | Canvas 渲染：自动选层（迟滞防抖）、指数平滑缩放、瓦片异步加载、粗层占位、单分辨率降级 |
| `js/metrics.js` | PerformanceObserver（measure/longtask）、FPS、堆内存采样、分层渲染基准 |
| `js/main.js` | UI 绑定、Worker 调度、降级策略 |

## 关键设计

- **金字塔构建**：高斯核 `(1,4,6,4,1)/16` 可分离两遍卷积；拉普拉斯层
  `L_i = G_i − EXPAND(G_{i+1})` 以 `Int16Array` 存残差，构建时同步验证重建误差（≤2/255）。
- **大图内存**：上采样按行条带（band）计算，中间缓存从 O(W·H) 降到 O(W·band)；
  每层瓦片立即写入 IndexedDB 后释放，主线程不持有原图（构建前只保留 ≤2048 的降级 bitmap）。
- **瓦片边界**：目标矩形「两边取整法」——相邻瓦片共享同一整数边界，无缝无重叠；
  边缘瓦片按实际部分尺寸存储与绘制。
- **缩放抖动**：视图指数平滑逼近目标（`1−e^(−k·dt)`），层选择带 ±0.6 log2 迟滞，
  瓦片未就绪时用更粗层子区域占位，避免闪烁与来回切层。
- **内存控制**：LRU 缓存带字节预算（UI 可调 16MB–1GB），超预算按最久未使用逐出；
  IndexedDB 持久化瓦片，刷新后可恢复。
- **降级**：Worker 构建失败 / 手动开启 → 单分辨率模式（仅最粗层瓦片）；
  极端情况 → 整图单 bitmap 渲染。
- **性能对比**：侧栏实时显示 FPS/帧耗时/缓存/堆内存/长任务；
  「分层渲染基准」逐层渲染 30 帧输出均帧/峰值耗时与内存表格；
  构建表展示每层尺寸、构建耗时、瓦片数、字节数、重建误差。


## 验收对照

- **金字塔构建正确**：常数图保持、拉普拉斯重建误差 ≤2、分条带与整体计算一致（单测覆盖）。
- **多分辨率渲染正确**：按 `-log2(scale)` 自动选层，缩放比与层对应关系实时显示。
- **缩放平滑**：指数平滑 + 层切换迟滞 + 粗层占位，滚轮/滑杆缩放无抖动。
- **瓦片边界正确**：切分重组无损（单测），UI 可开启瓦片网格叠加层目视验证。
