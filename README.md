# 图像金字塔 · 多分辨率渲染

基于 **Canvas + Web Worker + TypedArray + IndexedDB + PerformanceObserver** 的大图多分辨率渲染系统：在 Worker 中构建高斯/拉普拉斯金字塔并切片落盘，主线程按缩放级别调度瓦片渲染，支持平滑缩放、内存控制与单分辨率降级。

## 运行

需要通过 HTTP 访问（Web Worker 与 IndexedDB 不支持 `file://`）：

```bash
cd 本目录
python3 -m http.server 8000
# 打开 http://localhost:8000
```

## 功能与验收对照

| 验收标准 | 实现 |
|---|---|
| 金字塔构建正确 | Worker 内可分离 5×5 高斯核降采样（边缘钳制）；拉普拉斯层 `L = G - expand(G_next)`，Float32 计算、`(L+255)/2` 量化存储；构建时逐层校验重建误差（≤ 1 灰度级）并上报 |
| 多分辨率渲染正确 | 按 `round(-log2(scale))` 选择层级，视野内瓦片异步加载；缺失瓦片用更粗层级缓存垫底，缩放过程不闪空白 |
| 缩放平滑 | 相机当前值向目标值指数趋近（时间常数 ~90ms）；滚轮/双击/捏合均以光标为锚点；平移带惯性衰减；动画期间用低质量插值、静止后切高质量 |
| 瓦片边界正确 | 边缘瓦片按实际尺寸存储；绘制时目标矩形**两边独立对齐设备像素**，相邻瓦片共享取整后的边，无缝无重叠（E2E 像素级缝隙扫描验证） |

## 关键问题处理

- **大图内存**：金字塔构建全程在 Worker 内用 TypedArray 完成，逐层释放（8192² 构建时主线程 JS 堆仅 ~10MB）；原图不常驻主线程
- **构建耗时**：可分离核将 5×5 卷积降为两次 1×5 扫描；逐层进度上报；8192² 约 10s（6 层）
- **瓦片边界**：见上表；UI 可开启「显示瓦片边界」调试网格
- **缩放抖动**：目标边取整基于绝对坐标，瓦片整体一致移动；指数趋近消除回退抖动（E2E 验证 0 次方向反转）
- **内存控制**：LRU 瓦片缓存按字节预算淘汰（滑块 32–512MB），当前可见瓦片受保护；堆内存压力超 90% 时自动减半预算
- **降级单分辨率**：Worker 异常 / IndexedDB 不可用 / 手动切换时，退化为整图 `drawImage` 缩放渲染

## 性能对比

「运行基准测试」逐层固定视野测量帧耗时、瓦片数、缓存与堆内存，并与单分辨率模式对比，结果在右侧面板表格展示。实时面板显示 FPS、帧耗时、当前层级、缓存命中率、JS 堆（`performance.memory`）与长任务数（`PerformanceObserver` longtask）。

## 文件结构

```
index.html            页面与 UI
css/style.css         样式
js/pyramid-worker.js  Worker：高斯/拉普拉斯金字塔构建 + 瓦片切分 + IDB 落盘
js/viewer.js          渲染器：相机动画、瓦片调度、层级选择、单分辨率模式
js/tile-cache.js      LRU 瓦片缓存（字节预算 + 可见保护）
js/db.js              IndexedDB 封装（主线程/Worker 共用）
js/perf.js            PerformanceObserver + 堆内存监控
js/main.js            UI 接线、瓦片供给、基准测试、自动降级
```

## 持久化

瓦片与元数据存入 IndexedDB，刷新页面后自动恢复上次构建的金字塔，无需重建。
